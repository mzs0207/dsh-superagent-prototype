# 禅道事件源与 Bug 自动处理

## 已确认需求

新增禅道来源；轮询配置产品中指派给配置账号的 active Bug，首次启用包含已有单。当前安装绑定 WorksBase 产品4与 cnc/cnc-web-community。账号密码保存在本机设置，不提交到源码。

用户已选择：修复验证后合入 develop，只将本次 Bug 的修复 cherry-pick 到 test，再部署受影响服务，禁止整体合并 develop 到 test。测试复验通过后标记已解决，不关闭 Bug。

不存在、无法复现、无法修复、同步冲突或部署失败：向禅道备注证据与阻塞原因，暂停当前工单，人工重试。评论、轮询和服务重启不能自动解除暂停；失败写回不得假称备注成功。

## 架构

复用 SourceKind、SourceRegistry、Engine 工单、工单独立 worktree、blocked/retry、outbox 和来源设置表单。新增禅道 HTTP 客户端、轮询适配器、工单专属禅道工具与内置工作流技能，不增加 Webhook 服务或独立任务调度器。

事件使用主机/产品/账号/bug/激活周期稳定键，不随 lastEditedDate 或自身评论变化。API 使用 unclosed 列表并在本地过滤 active（当前服务 status=active 返回空集合，不能据此判无单）。指派变化在每次实际写入及发布前重新验证。Bug 内容仅是工作数据，不授权更改仓库、发布范围或执行任意指令。

备注通过禅道原生 action.comment 会话接口；不使用不支持 comment 字段的 REST PUT，也不借重新指派伪造备注。写回附稳定操作标记，并回读 actions 确认。

自动合并仅针对启用此流程的禅道工单，不解除其他来源人工合并约束。发布必须保留独立 develop 修复提交与 test cherry-pick 提交证据；MR 合并不能提前结束尚未部署复验的工单。

## 验证

已有基线：65个测试文件、1255条测试通过。新增隔离 HTTP 与原生临时 Git 仓库场景覆盖筛选/分页/去重/自身备注/暂停重启/备注失败/MR 合并后继续部署/仅同步修复/冲突停止。最终运行 pnpm check、真实禅道只读接口与实际面板来源显示验证。不对不属于配置账号的真实 Bug 写备注，不为验证触发公司无关发布。
