# 项目优化记录设计

## 目标与已确认范围

自动积累本项目运行证据，再记录经验证的优化经验。后续优化先查证据，不让记忆自行修改代码、提示词或权限。用户已选择“自动运行记录＋经验证的优化经验”。

## 记录内容

- 任务创建、启动、报告状态、结束、人工重试与恢复；仅保存匿名关联键，不复制任务标题、聊天、报告正文或身份。
- 副作用真实失败/成功和 worker 自动重试；暂停、等待槽位等 Later 不算失败。保存明确错误码，不能分类时明确 unknown，不推断根因。
- 任务总耗时、启动等待、单次副作用耗时；不把这些当作模型计算时间或 token 成本。
- 应用版本/构建标识、配置/提示词版本、模型配置指纹，以及已记录验证检查点的布尔投影。未记录不算成功。
- 优化经验包括问题、改动、验证、效果、关联证据、hypothesis/verified 状态。仅 verified 可同步记忆；证据缺失拒绝 verified。

## 存储与读取

复用现有 SQLite，新增由优化账本管理的两张表；运行记录保留90天，经验长期保存。不倒填历史、不复制原始记录。管理 API 提供有界分页、时间范围、分组统计与经验保存；现有控制脚本提供查询/JSON导出及从文件提交经验。仅回环管理接口开放，不扩展手机网关。

运行观察在现有事务内独立 savepoint 写入，观察失败通过独立 health 显示而不改变任务结果；回滚不产生虚假证据。无需逐事件调用模型或远端服务。

## 记忆边界

沿用本机私有 Hindsight 连接与持久 Effects 队列；本项目优化经验使用独立项目标签和用途标签，不带业务仓库标签，不进入业务修复记忆。只上传手动确认的脱敏经验，自动运行记录留本机；本地读取不依赖 Hindsight。历史只是待核实的参考，不是授权或真理。

## 验证

覆盖事务回滚、重启持久化、重复事件、状态转移、Later 与真实失败区分、人工/自动重试区分、敏感文本排除、验证门槛、分页/时间筛选、独立记忆标签和远端故障重试；使用真实 SQLite 和本地 HTTP 烟测。保持既有质量门禁。
